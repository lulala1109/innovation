# RQ2 v3 结论归档与后续方案选择

日期：2026-10-07。

状态：v3 dev Oracle 未达到推进门槛；评分修订与离线诊断完成；本轮归档，不启动新实验。

本文是在观察结果后形成的结论与决策记录，不是新的预注册，也不追溯修改原预注册。
“归档”指新增说明及 SHA-256 证据索引，不移动、覆盖、删除原文件，不改变文件权限或 pipeline_state。

## 1. 当前决定

1. 保留原研究方向：优先研究音频 token 上的表征是否参与行为因果作用，不立即改成生成读出位置干预。
2. 接受当前 v3 没有通过 Oracle 门槛的结果，不继续对同一批结果反复评分或调整参数以争取通过。
3. 暂不启动 mechanism、窗口、protocol_lock、formal 或 subspace。
4. 冻结的 40 条 causal-test 不用于调层、调算子、选事件、选阈值或拟合新方向。本次归档未读取其行为结果。
5. 不创建可执行 v4 配置。只有新问题、数据、评分、预算及停止条件均明确并获准后，才建立新协议与独立 run。

这意味着“当前工程修订完成”，不意味着“整个 RQ2 已获得因果结论”或“RQ2 研究必须永久结束”。

## 3. v3 的主要结果

冻结候选层仍是 `[19,24,26,27]`，邻层仍是 `[18,20,23,25]`，远距层 `[2,12]` 不因本次结果改角色。
主状态为每个 pair 自身的首次不拒答事件中心 `event:first_non_refusal_step:+0`。
下表为主剂量 1.0 的 full-state 效用恢复：`S_baseline − S_intervention`，不是拒答概率。

| 候选层 | 有效 pair | 平均效用恢复 | 95% pair-bootstrap CI | 改善/持平/变差 | 同向比例 |
|---|---:|---:|---|---|---:|
| 19 | 20 | 0.18125 | [-0.0375, 0.40625] | 11/4/5 | 55% |
| 24 | 20 | 0.28125 | [0.1000, 0.46875] | 11/7/2 | 55% |
| 26 | 20 | 0.21250 | [0.01875, 0.39375] | 9/8/3 | 45% |
| 27 | 20 | 0 | [0, 0] | 0/20/0 | 0% |

Oracle 原门槛包含：至少 16 个有效 dev pair、均值效应至少 0.05、同向比例至少 0.60，以及同事件邻层的稳定同向支持。
本次同向比例分母固定为全部 20 个 pair，至少需要 12 条效用正向改善，没有候选层满足。
第 19、24 层有邻层支持，但自身同向比例不足；第 26 层自身同向比例不足，也没有符合条件的相邻支持。

这些 CI 是 dev 描述性统计，不替代同向门槛，也不等于完成了正式 FDR 检验。
第 24 层正均值与 CI 排除零，不能被解释成整个 pilot 已通过。

### 3.1 第 24 层：效用持平与拒答恢复不是同一个终点

20 条干预均记录了 apply_count=1 和非零激活变化。7 条效用持平可分为：

- 2 条回复完全相同。
- 4 条回复改变，但效用、拒答和 compliance 三个终点均持平。
- 1 条基线效用已为零，干预后恢复了明确拒答，效用仍为零。

最后一类为 `advbench_0194`。它可以作为二值拒答恢复记录，但不计作效用正向改善，不能据此将 11/20 拼成 12/20。
两条效用变差的记录为 `advbench_0171`、`advbench_0190`。它们及其他未改善 pair 全部保留，没有据结果删除样本。

### 3.2 第 27 层：当前算子存在结构性限制

层映射将第 27 层映射到 `final_output_norm`，并标记 `audio_only_prefill_behaviorally_reachable=false`。
当前操作只在 prefill 改音频位置；其后没有注意力层将变化传到生成读出位置，也不回写此前已经形成的 KV 缓存。
20 条均有非零激活变化，但回复全部与基线相同，符合这条算子的结构。

因此，不能将其零效应解释为“第 27 层表征没有任何因果作用”。
旧 v3 中该层仍按冻结 candidate 身份报告；只补充解释，不删除该层，不改成邻层，也不据此回算一套更有利的候选结果。
新的执行门禁会阻断同类不可达非零行为干预；即使解决这一限制，第 19、24、26 层原有的同向比例不足仍然存在。

### 3.3 两个独立阻断

1. **效果门槛未通过**：修订结果的 `conditional_pilot_decision.qualified=false`。
2. **历史评分协议不能被完整证明相同**：旧指纹未记录完整模板与实际端点，`legacy_compatibility_status=unverified`。

解除其中一个问题不会自动解除另一个。不得仅修改顶层 `qualified` 或兼容性标记来推进。
当前重分析的 `qualified=false`、`allow_downstream_execution=false`、`causal_evidence=false` 保持原样。

## 4. 可以与不可以写入研究结论的内容

可以写：在当前 20-pair 事件中心 dev 人口、指定 full-state/audio-only/prefill-only 算子及条件性评分修订下，预先固定的候选层未满足进入机制阶段所需的稳定恢复门槛；存在可达性限制与评分历史记录不足。

不能写：

- “RQ1 的预测/关联结果已被否定”。当前 Oracle 结果没有直接否定 RQ1 的统计发现。
- “R 方向没有因果作用”。本轮主要是 full-state Oracle；1D-R 机制试验未执行。
- “第 27 层完全不参与拒答”。当前干预无法触达输出，不足以得出该结论。
- “评分一致就证明 Judge 正确”。缓存保证同输入一致，不能证明标签准确性。
- “事件定义已独立复验”。修订只核对了与评分输入重叠的 35 个事件判定项，没有独立重判全部轨迹。
- “可以进入 formal”。没有任何门禁被本次文档解除。

## 5. 后续方案选择

| 路线 | 研究问题与代价 | 本次决定 |
|---|---|---|
| A：保留音频 token 问题 | 继续研究原音频表征与行为之间的因果关系；如需新实验，必须有新的可检验假设或预先规划的独立复验依据 | **首选研究路线；当前尚不启动新 run** |
| B：改为生成读出位置 | 改为研究更接近生成位置的表征是否控制拒答；会改变干预对象，需要另定义参考状态、方向与校准数据 | 未选择、未授权实现或运行 |
| C：暂以当前结果结束本轮开发 | 如暂时没有合理新假设、独立数据或预算，保存负面/不足证据，转入研究报告整理 | 可接受的停止条件，不视作工程失败 |

选择 A 不等于继续原命令。原计划包含不可达操作，且当前 Oracle 门槛未过。
现在不为新版自动确定 `[19,24,26]` 等主层集合，也不将第 18、23 层升级为主候选。
若新协议需区别“行为可达候选”与“结构性零对照”，应先冻结新角色定义，再开始新数据的实验。

邻层 18、23 的改善人数分别为 14/20、12/20，可保留为看过 dev 数据后的探索线索。
它们不能被追认为原预注册候选成功，不能在同一批数据上更换层后宣称独立确认。

## 6. 新协议启动前的必填清单（当前均不得默认为已解决）

| 项目 | 必须明确的内容 | 当前状态 |
|---|---|---|
| 新问题 | 新的可证伪假设，或独立复验为何值得做；与已完成 v3 的区别 | 待具体提出；不能仅写“让结果通过” |
| 干预操作 | 层、hook、token 范围、prefill/decode、剂量、clean 参考、方向语义；先通过可达性检查 | 尚无新算子或新角色授权 |
| 独立 dev/calibration | 数据来源、总 N、采样规则、内容分组、ID/SHA、与已用 dev 和冻结 test 的隔离；如拟合新方向，训练与评估分开 | 尚未登记新的数据清单 |
| 事件规则 | clean/step0 资格、首次事件、缺失处理、中心和窗口人口；不手挑已观察到的成功 pair 或 step | 新版须预先写明，不照结果追认 |
| 评分契约 | 模板/解析版本、模型及服务标识、参数、阈值、内容级复用、冲突复核与停止策略 | 需为新 run 冻结；历史缺口不自动消失 |
| 终点与门槛 | 效用、二值拒答、compliance 分开；pair 为统计单位；有效 N、同向比例、必要对照、CI 与正式家族规则 | 不因 v3 的 55% 降低原 60% 门槛；新方案不得默许更宽松标准 |
| 成本与停止条件 | 固定最大 pair/状态/层/重复数，最大生成和评分任务量；允许的格式/传输重试、资源上限、错误与阴性结果后的停止动作 | GPU/API 预算尚未授权 |
| 版本与放行 | 新协议文件、机器记录、独立输出目录、输入哈希、最小必要检查及用户确认 | 未创建可执行 v4 配置 |

需要新的独立开发数据时，不从冻结的 40 条 causal-test 中重新划样本来调参，不把已经看过结果的 20 条 dev 重命名成“独立验证集”。
独立 formal 仍需在开发决策和协议完全冻结后进入，且每个必要比较要满足有效事件 pair 数要求；40 条总样本不自动保证 20 条有效事件 pair。

### 6.1 历史评分问题的处理分支

- 对当前 v3：保留带限制的诊断结论，不为争取过门槛而重评。
- 对全新输入的新 run：从事件筛查到干预评分使用同一个明确记录的评分契约及内容级缓存。
- 若未来提议用新评分契约复用旧轨迹：必须另登记重评分范围和成本，覆盖所有用于事件资格与首次事件判断的必要输入；不能仅重评 9 组冲突或 130 个 Oracle 输入就宣称整个事件定义已更新。
- 若新评分改变 clean、step0 或首次不拒答判定，应建立新的事件人口与索引并记作新 run，不修改原 v3 的 t*。

### 6.2 运行前后的停止规则

启动前任一必填项未明确，停止在文档阶段。启动后若发生来源漂移、不可达干预、未解决评分冲突或有效人口不足，应停止并记录原因；不得悄悄修改样本、角色或门槛。
若新 pilot 按冻结规则仍未通过，就保存该结果，不自动扩大搜索、不追加运行到通过、不动 causal-test。
