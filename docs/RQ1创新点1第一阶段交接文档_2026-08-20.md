### 2.3 正式 Standard PGD 的固定要求

- `method=standard`。
- `init_mode=zero`。
- 禁止 early stop。
- 保存 `t=0,1,...,T` 全部状态，不能只保存 0/25/50/75/100。
- `t=0` 的 `delta` 必须精确为零。
- 正式运行时使用：

```text
--method standard --init-mode zero --no-early-stop --save-all-steps
```

### 2.4 行为标签必须离线判定

- PGD backward 过程中不运行 response generation 和 StrongREJECT judge。
- 每个 checkpoint 保存后，单独执行 response generation。
- 再用单独 pass 执行 StrongREJECT。
- `attack_success` 或 `target_substring` 不能推断 refusal。
- 标签生成失败必须记录为 `unknown`，不能自动当作拒绝或服从。
- `unknown`/缺失标签不会阻止 held-out checkpoint 的 hidden-state replay，但不能作为确定的行为事件。

### 2.5 正式 RQ1 禁止兼容模式

以下参数只用于检查历史 artifact，不得用于正式 RQ1：

```text
--allow-missing-directions
--allow-unverified-provenance
```

正式 analyzer 会拒绝：

- legacy v1 probe；
- 缺失 class-mean directions 的 score；
- 模型或训练 payload provenance 未验证的 score；
- 非 `measurement_val/trajectory_candidate` 的轨迹。

### 3.5 H/R probe、指标与独立方向

主要文件：

- `experiments/train_safety_probes.py`
- `tests/test_train_safety_probes.py`

完成内容：

- H probe 与 R probe 始终独立训练，不生成合并安全分数。
- CLI 默认 5-fold pair-grouped OOF CV。
- 同一个 `pair_id` 不跨 fold。
- 新增指标：
  - AUROC
  - F1
  - balanced accuracy
  - confusion matrix
  - pair-cluster bootstrap 95% CI
- 每个 fold 仅使用 fold-train 估计 class means 和 direction，避免验证泄漏。
- OOF 输出包含 probe probability、direction projection 以及二者 Spearman 一致性。
- CV 完成后，用全部合格的 measurement-train rows 训练最终 probe。
- v2 checkpoint 保存：

```text
directions[target][layer] = positive_mean - negative_mean
class_means[target][layer] = {negative, positive}
```

- direction 投影定义：

```text
center = (positive_mean + negative_mean) / 2
projection = dot(x - center, direction) / ||direction||
```

- `experiments/replay_stage1_trajectories.py`
- `tests/test_stage1_trajectory_replay.py`


### 3.8 RQ1-a/b/c 分析与报告

主要文件：

- `experiments/analyze_stage1_rq1.py`
- `reporting/generate_stage1_rq1_report.py`
- `tests/test_stage1_rq1_analysis.py`
- `tests/test_stage1_rq1_reporting.py`

完成内容：

- Layer × Attack-Step H/R mean、variance、SE、pair-bootstrap CI。
- 相对 `t=0` 的 `Delta H`、`Delta R`。
- 显式 phase：
  - early：`0 <= progress < 1/3`
  - middle：`1/3 <= progress < 2/3`
  - late：`2/3 <= progress <= 1`
- attack loss 与每层 H/R 的 Spearman 关系。
- layer profile 跨样本可重复性：
  - ICC(2,k)
  - leave-one-out Spearman
  - bootstrap 时按完整 pair profile 重采样，并在每个 replicate 内重新计算 LOO
- 每层 slope、FDR 校正。
- mixed-effects：

```text
score ~ C(layer) * progress + (1 | pair_id)
```

- H/R 联合比较：

```text
score ~ state_type * C(layer) * progress + (1 | pair_id)
```

- 行为事件对齐：
  - first refusal weakening
  - first non-refusal
  - first compliance
- 未收敛、方差触边、信息矩阵奇异或 nested LL 异常时，不输出可误读的 LRT/系数 p 值。
- 报告不会预设“H 稳定、R 下降”为结论，只将其作为待检验假设。
- 第一阶段不声称因果关键层；activation patching 属于后续研究阶段。
- 输出 CSV、JSON、Markdown；安装 matplotlib 后可选输出热图和轨迹图。

```bash
  --manifest dataset/processed/stage1/manifests/jbb_trajectory_attached.csv \
  --output-dir outputs/stage1/replay/val_hidden \
  --model qwen-3b \
  --model-id model_weights/Qwen2.5-Omni-3B \
  --device cuda \
  --dtype bfloat16 \
  --layers all \
  --token-span audio \
  --pooling mean
```

预期：

- 20 个 case `.pt`；
- 每个 case 101 个 step；
- `index.json.complete == true`；
- 所有 case 的 layer/hidden size/step grid 一致。

该步骤支持 resume。不要在同一个 output dir 中更换模型、dtype、layers、pooling 或 manifest。

## 7. 正式运行前必须确认的事项

1. Standard PGD 的 `eps/alpha/steps/loss_type/kappa` 是否与最终实验设定一致。
2. StrongREJECT provider、judge model、threshold 和认证配置是否固定。
3. GPU 显存是否足够加载 `model_weights/Qwen2.5-Omni-3B`。
4. 磁盘是否足够保存 100 个 case × 101 个 checkpoint，以及 replay hidden states。
5. 是否先用 1～2 个派生 case 做 smoke test，再使用全量不可变 manifests。
6. 所有正式命令、随机种子、环境版本和输出根目录是否记录。
7. train/held-out 是否始终通过 `pair_id` 隔离。
8. 是否存在 `unknown`、失败 case 或少于目标 80/20 的有效 pair；这些情况必须报告，不能静默补标签。

## 8. 第一阶段之后的工作

完成并解释 RQ1 结果后，再进入后续阶段：

- 根据跨样本 Layer × Step 结果提出候选层/阶段；
- 做独立复现或稳定性检查；
- 再进入 activation patching、因果定位或 Dynamic Safety Bottleneck 等后续研究问题；
- 第一阶段的相关性结果不能直接作为“关键层具有因果作用”的证据。
