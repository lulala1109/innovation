配置创建时绑定本文件与新增实现的 SHA。运行开始后不得修改或重新绑定；工程失败时保留文件并另立修订方案。

## 人口和范围

- 精确复用 `qwen7b_advbench_post_oracle_explore_v1_run01` 的 20 条 dev，不按结果剔除或换样本。
- 使用原首次不拒答事件，保留 3 条中心零分样本。仅 L19、L24，完整 audio token span，prefill 一次。
- 不新增 PGD、不使用 40 条 causal-test、不运行反向、窗口、多层联合、subspace 或 formal。
- 模型、RQ1 方向/中心/参考统计、clean 音频、事件 checkpoint 与生成参数沿用冻结来源链。
- 生成保持贪心、100 新 token。冻结模型接口仅返回文本，实际生成 token 数及停止原因不可用，不从字符数推断截断。

## 正交干预

R/H 单位化。R 恢复沿用冻结算子：以 clean 与当前事件音频 token 均值的 R 投影差 `g` 作为位移。
主剂量只有 1，无剂量选择；sham 沿用冻结恒等算子。

H 对照先计算 `H_perp = normalize(H - dot(H,R)*R)`，再沿 clean–事件差在 H_perp 上的符号移动，位移幅度 `abs(g)`。
随机对照先采样标准正态向量，剔除 R 分量后归一化，以固定随机符号移动 `abs(g)`。
这检验几何重叠解释，不把 H_perp 称为语义纯 H。

随机主 seed 为 42，replicate 为 0、1、2。严格沿用仓库的 seed 派生：
对 seed/pair_id/state_key/layer/replicate 组成对象取 canonical SHA 前 16 位，转整数并取模 `2**63-1`；
然后加 `1000003*replicate` 作为 CPU Torch Generator seed。
与操作草案中建议的三个直接 seed 不同，这里明确冻结逐 pair/层派生，避免把共享随机向量误认为独立抽样。
随机重复先在 pair 内平均，独立统计单位仍为 20 个 pair。

每 pair×层：R 一次、H_perp 一次、random_perp 三次、sham 一次，共 `20×2×6=240` 条干预。
另真实生成 20 条无 hook 基线，共 260 条生成；不是把旧回复导入冒充新生成。
新基线必须与冻结事件回复完全一致，40 条 sham 必须与本轮基线完全一致；不一致在评分前停止。

## 数值门禁

在任何新行为生成/Judge 前，对全部 240 个条件执行模型诊断前向并存逐项审计。
hook 仅应用一次，decode 单 token 只跳过，其他非预期长度停止；仅允许音频位置，禁止位置缩放。

固定工程容差（不是效应成功门槛）：

- 正交剩余方向范数至少 `1e-6`，R 缺口绝对值至少 `1e-6`；不满足则整轮停止，不剔除该 pair。
- R 投影目标误差，或正交对照的实际 R 投影泄漏，至多 `1e-4 + 0.02*abs(g)`。
- 实际均值位移对理论幅度偏差，至多 `1e-4 + 0.05*abs(g)`。
- 对照与同 pair 同层 R 的实际均值位移、全张量位移分别匹配，偏差至多 `1e-4 + 0.05*R实际范数`。
- sham 位移和投影变化严格为零；对照的 token 位置、干预前和 clean 参考投影一致。

全部通过才将 numeric_preflight 标为完成。实际生成的诊断前向与生成 hook 继续执行数值检查，生成完成后再次执行配对范数门禁。
有限精度不能成为按行为结果调整容差的理由。失败保留审计，不自动加剂量、改 seed、改层或进入反向实验。

## 分析与结论

报告所有四类干预的效用、明确拒答和 compliance 变化。
配对比较为 R-H_perp、R-random_perp 与 R-sham，各报告三个终点；随机重复先在 pair 内平均。
使用现有 pair bootstrap，2000 次、seed 42、描述性 95% 区间，不声称正式 FDR 或确认性成功。
主要问题是 R 是否与匹配的正交对照可区分，不以 R 相对基线的降分独自证明方向特异性。
不按中间行为效果停止、筛样或追加条件；允许因工程、来源、预算、请求状态异常停止。
数据独立性人工复核、输出语义人工复核及部署防御仍未完成。

## 命令

在仓库根目录、现有 `whisper_default_v2` 环境中执行：

```bash
python experiments/rq2_orthogonal_calibration.py prepare
python experiments/rq2_orthogonal_calibration.py validate
python experiments/rq2_orthogonal_calibration.py run \
  --from numeric_preflight --through numeric_preflight \
  --acknowledge-cost --accept-exploratory
python experiments/rq2_orthogonal_calibration.py run \
  --from calibration_generate --through report \
  --acknowledge-cost --accept-exploratory --direct
```

`prepare/validate/plan/status` 不构造模型或发出 API 请求。`prepare` 仅首次创建独立配置/来源记录/空账本，重复执行校验而不重置。
`numeric_preflight` 使用 GPU，仅诊断前向，不生成回复、不请求 Judge。
`--direct` 仅让本进程的评分端点绕过代理；使用代理环境可省略，不改 `.env` 或冻结端点。
可先执行 `check-endpoint --direct`，它仅做不带凭据的 HTTPS 探测，不验证 key 或账户余额。
正常中断重用同一 run 命令，已完成阶段验证哈希后跳过；已提交生成记录可恢复，不清空输出目录。
未决 API 账本不会因重复命令自动继续，需单独核查，不能沿用旧 attempt 234 恢复命令处理新账本。

输出目录：`outputs/stage2_rq2/calibration/qwen7b_advbench_orthogonal_calibration_a_v1_run01/`。
最终报告 `rq2_orthogonal_calibration_report.md`，逐项效应 `calibration/pair_effects.csv`，配对区间 `calibration/analysis.json`。
