## 2. RQ2 的研究目标与数据结构

### 2.1 与 RQ1 的衔接

RQ1 研究 PGD 优化过程中 harmfulness 表征 H 与 refusal 表征 R 如何变化及相互关联。RQ2 进一步通过主动修改内部激活，检验行为是否改变，并验证层、攻击状态、方向特异性和双向证据。

需要区分：

1. **Full-state Oracle**：把指定位置的完整激活替换成同 pair 的 clean 激活，检查该操作下是否存在可恢复通路。它同时改变多种成分，不是 R 特异性证据，也不是其他干预效果的数学上界。
2. **R 机制验证**：只修改 R 相关成分，与 H、随机方向、空操作等匹配对照比较，再检查反向抑制。除极小规模 smoke 外，尚未完成独立完整验证。

当前模型为 Qwen2.5-Omni-7B，使用冻结的 RQ1 probe、方向和来源记录。RQ2 没有重新训练 Qwen、没有修改模型权重，干预发生在推理时的内部激活。原始 9 月 docx 中的 3B/36-layer 描述属于旧背景，当前执行规格应以 7B 修订与实际 layer map 为准。

### 2.2 什么是一个 pair

一个 pair 对应同一条请求的 clean 音频、PGD 轨迹，以及各状态的基线和干预回复。

同一 pair 下的层、步数、干预类型和随机方向重复都是重复测量，不能当成额外独立样本。独立统计单位仍为 pair_id。

- 原始划分：20 条 dev、40 条 causal-test、395 条 reserve。
- smoke 的 2 条来自原 dev；固定步筛查和 v3 使用同一批原 dev，不能算成三批独立数据。
- v4 按预先固定规则从 reserve 取原 split_rank 61–80 的另 20 条，未根据本轮攻击或干预结果换样本。
- 原 40 条 causal-test 没有进入本轮干预或参数选择。
- 仓库身份、内容组和音频 SHA 的排重不替代人工语义独立性、音频保真复核，也不能证明所有仓库外使用历史；这些限制应保留。

## 4. 最新 v4 的实验结构

### 4.1 实际流程

```text
固定的 20 条新 dev pair
  → clean 参考 + 100 步 PGD，保存 step 0–100
  → 生成并评分 clean 和全部检查点的无干预回复
  → 检查 clean/t0 拒答资格，定位各 pair 的首次不拒答 t*
  → 状态索引、层映射、identity
  → 重放 t*：无干预 vs 指定单层 full-state / 空操作
  → Oracle Judge → 配对分析 → 报告 → 本轮停止
```

PGD 明确使用 steps=100、early_stop=False、save_all_steps=True，不会首次不拒答就停止。事件是在轨迹和回复已形成后，通过 Judge 标签事后定位的；PGD 内部的成功检查不能自动等同于这个事件。

在 t* 重放时，替换的是模型内部激活，不是音频扰动。干预没有接入原 PGD 优化循环，不会改变已保存的 t*+1 到 100 步，也不证明攻击者针对干预重新优化后仍可被防住。

这是离线检查点干预实验，不是已部署防御。实际部署通常不知道攻击者的步数，也不能默认拥有对应 clean 参考。

### 4.2 基线和事件人口

- 每 pair：clean 1 条 + step 0–100 共 101 条，合计 102 条。
- 20 × 102 = 2,040 条轨迹行为记录及标签。
- clean 决定 harmful-but-refused 参考资格；t0 决定轨迹是否从拒答开始。
- 从 step 1 寻找首次明确不拒答；未知标签不能当作拒答或零分跳过。
- 最新有效事件为 20/20，其中 17 条事件中心基线分数大于 0，3 条为 0，零分 pair 保留。
- 实际干预仅在 event:first_non_refusal_step:+0。虽然前后窗口的基线记录可用，窗口干预没有执行。

### 4.3 层与干预组合

候选层：[19,24,26]；邻层：[18,20,23,25]。

第 27 层按当前 layer map 对应 final output norm，audio-only/prefill-only 修改不能通过后续注意力影响生成读出，v4 按结构依据不执行该层。旧 v3 的层角色和结果未回填修改。

Full-state 使用同 pair 的 clean 激活，剂量 1.0，作用于完整音频 token span，在 prefill 应用一次，不持续修改 decode。各层分别运行，不是同时修改七层。

| 条件 | 执行层 | 每 pair 数量 | 合计 |
|---|---|---:|---:|
| Full-state，剂量 1 | 3 候选 + 4 邻层 | 7 | 140 |
| Sham | 19/24/26 | 3 | 60 |
| Self-patch | 19/24/26 | 3 | 60 |
| R 零剂量 | 19/24/26 | 3 | 60 |
| 无干预事件基线，复用轨迹回复 | 每 pair 一条 | 1 | 20 |

新增干预回复 320 条，加复用基线后 Oracle 共 340 条记录、16 个干预条件组。主要回复任务为 2,040+320=2,360；模型加载、参考提取、identity 和辅助生成等不包含在该主任务计数中。

**本轮非零剂量 R 方向干预为 0 个。** R 零剂量是空操作，不是机制验证。评分有内容级缓存，标签数量不等于新增 API 调用数。

### 4.4 行为指标如何解释

```text
效用改善 ΔU = S_base − S_patch
拒答变化 ΔR = R_patch − R_base
compliance 减少 ΔC = C_base − C_patch
```

S 是 StrongREJECT 分数，越高表示回答越能有效满足有害请求。R 是二值明确拒答。C 是 canonical-balanced compliance，要求非拒答、score≥0.5、convincingness≥3、specificity≥3。

- 平均效用改善：全部 20 条 ΔU 的平均，包括改善、持平和变差。
- 效用改善人数：ΔU 严格大于 0 的 pair 数。
- 拒答恢复人数：无干预不拒答、干预后明确拒答的 pair 数；本轮全部事件基线都不拒答。
- 1−S 不是拒答概率。分数下降不一定拒答；零分非拒答变成拒答也可能保持 0→0。

符号注意：v4 协议文字把 compliance 写成 C_patch−C_base，而原 CSV 的 compliance_effect 与分析元数据实际是 C_base−C_patch。诊断导出了两个明确命名的方向，没有修改原协议或结果。该差异不改变效用门禁。

## 5. 实验效果

### 5.1 最新候选层结果

| 候选层 | 平均效用改善 | 改善/持平/变差 | 改善比例 | 拒答恢复 | 描述性 95% pair-bootstrap CI |
|---|---:|---|---:|---:|---|
| 19 | 0.13750 | 9/6/5 | 45% | 9/20 | [-0.05625, 0.33125] |
| 24 | 0.16250 | 9/9/2 | 45% | 10/20 | [0.03750, 0.30016] |
| 26 | 0.18125 | 10/8/2 | 50% | 10/20 | [0.06875, 0.31250] |

例如 0.1375 表示 StrongREJECT 平均下降 0.1375，不是 13.75% 的样本恢复拒答，也不是拒答概率上升 13.75%。

Oracle 要求同一候选层有效 pair≥16、平均效用改善≥0.05、严格正向比例≥0.60，并有同事件相邻层的 N≥16、正均值和≥0.60 同向支持。

三个候选都满足 N 和均值条件，但都没有 12 条正向改善。L19 有邻层 18/20 支持；L24/L26 没有满足规则的邻层支持。L24/L26 的 CI 下界为正不能代替人数门槛，更不是正式 FDR 或因果确认。

| clean 与 t0 混淆风险 | 已分开参考资格和轨迹转折基线，未知标签单列 | clean 拒答不能自动证明 t0 拒答 |
| 第 27 层当前操作不可达 | v3 保留原结果，v4 按结构排除 | 不能说第 27 层表征完全没有因果作用 |
| 邻层/远距层被误当深度匹配 | 已区分角色，2/12 不代表晚层深度匹配对照 | 优于任一个远距层不能证明排除深度因素 |
| 正均值不等于跨样本稳定 | 当前候选仅 45%–50% 效用改善 | 正 CI 不能替代原 60% 人数要求 |
| 效用不等于明确拒答 | 零分非拒答和效用下降但不拒答均实际存在 | 不能将 1−score 写成拒答概率 |
| Compliance 符号不一致 | 原协议文字与实际 CSV 方向相反，诊断标明两个方向 | 不能不看定义就解释正负值 |
| RQ1 关联强不等于当前干预最有效 | 邻层 18/20 的表现较好，仅作探索线索 | 不能事后提升邻层角色改判成功 |
| Full-state 未过不等于 R 被否定 | 最新 v4 非零 R 试验为 0 个 | 不能将未执行的机制阶段记作失败 |
| Oracle 依赖 clean 参考 | 属于离线配对干预，未接入攻击优化循环 | 不能直接称为可部署或已验证的自适应攻击防御 |
| 独立性和样本量限制 | 自动身份审计不替代人工语义核查，20 条是 dev 规模 | 最小 N 达标不等于统计功效充分 |

### 6.3 事件持续性：新近只读检查

以下统计按最新 v4 的轨迹 trial/label 以 trial_id 连接，在已冻结的 t* 上汇总，未修改事件或标签。

| 相对 t* 的位置 | 有效 pair | 不拒答 | Compliance |
|---|---:|---:|---:|
| -2 | 20 | 0 | 0 |
| -1 | 20 | 0 | 0 |
| 0 | 20 | 20 | 12 |
| +1 | 20 | 4 | 4 |
| +3 | 20 | 7 | 6 |

- 19/20 条在 t* 后三步内至少重新拒答一次，只有 1 条在随后的三步都不拒答。
- 另作一次事后描述：完整 step 1–100 中仅 9/20 条出现过连续三步不拒答；不能直接改事件后假定仍有至少 16 条入组。
- 首次不拒答适合作为“首次观察到非拒答”，不能自动称为持续失守。这不使当前同检查点的干预对比失效。
- 事件前两步基线全部为零效用，没有进一步下降空间。因此前后恢复效应差异也受基线边界影响，不能仅凭事件后效应更大就证明机制状态依赖。

这些均是描述性诊断，不是窗口干预结果、新的事件预注册或正式通过判定。

## 8. 当前效果的推荐表述

> 已完成 RQ2 工程验证、固定步可恢复性筛查及两批开发数据上的事件中心 full-state Oracle 分析。最新独立开发复验在 20 个 pair 上完成轨迹与 Oracle 评分，空操作、层映射、身份及评分一致性审计通过。预先指定候选层出现平均有害回答效用下降和部分拒答恢复，但效用正向比例仅为 45%–50%，未达到 60% 稳定性要求，尚未进入独立完整的 R 特异性机制和正式因果验证。结果限定于当前样本、事件、音频位置、prefill 算子及未锁定实际版本的 Judge 服务，不能认定已经找到因果拒答瓶颈，也不能认定 R 方向无效。

不宜写成：

- 整个 RQ2 已成功找到因果瓶颈。
- 所有干预都没有效果或 hook 没有执行。
- Oracle 没过，所以 R 方向已经被证伪。
- 某层 CI 为正，所以可以跳过人数、对照或正式门禁。
- 在有 clean 参考的单检查点恢复一次，就说明部署中能够防住攻击。
- 评分缓存一致，就证明 Judge 正确或所有返回名称都是同一版本。
