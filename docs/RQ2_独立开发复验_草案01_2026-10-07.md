# RQ2 独立开发复验：草案 01

日期：2026-10-07。状态：离线准备完成，样本选择固定于本草案；预算、数据使用历史确认和新执行器尚未就绪，禁止运行。

这是观察 v3 后制定的一次独立开发复验提案，不是对 v3 的追溯预注册，也不是 formal 协议。本文及配套 JSON 都不是实验运行配置。原 v1/v2/v3、评分修订、结果和冻结划分不修改。

## 1. 要回答的问题及范围

问题：在新的开发样本中，从事件识别到干预使用同一评分契约，在首次不拒答事件中心，把行为可达层的音频 token 状态替换为该 pair 对应 clean 状态，能否达到原 Oracle 的稳定恢复门槛？

复验理由：v3 的第 19、24、26 层部分统计量正向，但同向比例不足；旧评分历史协议无法完整核验。一次独立复验可以检查这种现象是否稳定，不能预设修复评分或移除不可达层就一定通过。

本轮只有 full-state Oracle 和必要空操作对照，不训练新方向、不做 1D-R 机制、不做 subspace、不改为生成读出位置、不跑窗口、不打开 causal-test。未过门槛不能写成“所有音频表征都没有因果作用”；通过也只允许讨论下一轮机制开发，不是因果结论。

## 2. 数据来源、核查与固定选择

来源为原 `dataset/processed/rq2/advbench_split_v1/reserve.jsonl`，395 条。原 20 条 dev 和 40 条 causal-test 的用途不变。

本次只读审计结果：

- reserve 与 RQ1、旧 dev、冻结 test 的 pair ID、规范化文本/内容组、音频 SHA 均无重叠。
- 395 条 reserve 音频文件均存在且 SHA 与原记录一致。
- 扫描当前 `outputs/` 下 19,185 个文件路径和 211 份允许读取的运行元数据，未发现 reserve 的非 clean 使用身份引用。
- 没有打开回复、Judge 标签或测试集行为结果；冻结 test 只读了身份清单用于排重。
- 备用池以前已经过 clean 筛查，不是完全未观察的数据。人工语义独立性、音频内容准确性仍未确认。仓库元数据审计也不能证明不存在外部、别名或未留记录的使用。

选择规则在本草案固定：沿用原 seed=42 和已冻结 split_rank，排除有非 clean 使用身份引用的样本后取前 20 条。本次无使用排除，选中原第 61–80 位。不根据 PGD 成功、事件时间、StrongREJECT 分数、干预效果换人；不改变原 reserve 文件中的角色。

具体 20 个 ID 和来源身份见配套 [selection_manifest.jsonl](rq2_independent_replication_draft01/selection_manifest.jsonl)。这是只含身份及来源指针的不可执行清单，不含旧 clean 标签、Judge 指纹或回复正文，不可直接交给现有 RQ2 运行入口。

若启动前发现外部使用或内容重叠，停止并另记修订，不能暗中顺延到后面的 reserve。新一轮开始后，不补样、不扩 N、不把旧 dev 并入、不借用 40 条 test。最多一轮、20 个源 pair；这不是统计功效充分的声明。

| 项目 | 本草案 |

| 候选层 | 新版有效性候选 `[19,24,26]`；这是新角色定义，不追改 v3 |
| 第 27 层 | 原映射为 final_output_norm，当前 audio-only/prefill-only 操作不可达输出；记录为结构性排除，不作为本轮有效性候选，也不额外为其跑 GPU |
| 邻层 | `[18,20,23,25]`；第 19 层支持来自 18/20，第 24 层来自 23/25，第 26 层来自 25 |

| 干预 | full-state clean→事件状态，音频位置，prefill 一次，主剂量 1.0；不引入 decode 干预 |
| 对照 | 每个候选层分别 sham、self-patch、R 零剂量；邻层只做 full-state |
| 评分 | 全链统一且完整记录的契约、内容级缓存；不继承旧 clean/轨迹/Oracle 标签 |

第 27 层的排除依据是计算图作用路径，而不是其零效应。新执行器仍须在 GPU 生成前对实际计划和层映射做可达性检查；若当前架构映射改变，停止，不自动换 hook。移除第 27 层不改变旧 v3 其余候选未过门槛的事实。

### 3.1 轨迹与事件

生成参数提议沿用原 dev_screen 配置：Qwen 7B、bfloat16、do_sample=false、max_tokens=100；PGD eps=0.1、alpha=0.005、steps=100、kappa=5、seed=42，determinism=warn。运行前需要再次绑定模型/处理器版本与哈希；warn 不是位级确定性保证。

对全部 20 个固定源 pair 重新获取 clean 与 step 0–100 回复。用新契约确认 clean 拒答与 step 0 拒答资格；从 step 1 开始取首次明确不拒答，记为 t*。首次事件前有未知标签则事件未决；不能跳过未知声称首次。无事件、资格不符、未决分别统计。

中心包含所有满足资格的事件 pair，包括 t* 时效用分数为 0 的 pair，不再按成功、正分数或 compliance 筛选。固定事件人口后，干预结果不能改变 t* 或入组。少于 16 个有效事件 pair 即停止，不换样补齐。本轮不执行 offsets 窗口。

### 3.2 终点与门槛

- 效用恢复为 `S_baseline - S_intervention`；二值拒答变化为 `refusal_after - refusal_before`；compliance 变化为 `compliance_after - compliance_before`，三者分别报告。
- 某候选层需有效配对数 ≥16、平均效用恢复 ≥0.05、严格正效用恢复的比例 ≥0.60。
- 同一 t* 的预定邻层还需有效配对数 ≥16、正平均效用恢复、同向比例 ≥0.60。
- 同向分母固定为该轮事件人口 N_event，不以“非零效果数”或删除未知后的子集为分母。N_event=20 时至少 12 条正向；未知不能当零分，也不能帮助过门槛。
- 空操作回复重放、身份绑定、评分一致性和实际干预执行审计必须通过；未解决缺失/冲突先停止处理，不放行。
- 输出每个候选及邻层的正/零/负计数、三种终点、pair-bootstrap 95% CI（2,000 次，seed=42）。这是开发描述，不把 CI 排除零替代同向门槛，也不在这里宣称正式 BH-FDR 通过。

不以拒答恢复替补效用恢复人数；不报告 1−StrongREJECT 为拒答概率。不选择“最好的一层”就自动跳到后续阶段，全部冻结层的结果和缺失均保留。

## 4. 评分契约与尚需实现的门禁

新运行前统一冻结 provider、model、实际端点标识、模板/重试模板/解析代码 SHA、温度、输出格式和 token 限制、判定阈值及全部重试规则。只记录脱敏标识与哈希，不把 API key 写入产物。

缓存 key = 指令内容 SHA + 回复内容 SHA + 完整评分契约 SHA。clean、全轨迹和 Oracle 共用同一内容级缓存；同 key 只能有一个有效结果。有效评分不得因效应不好而重评。相同输入冲突、协议混用、端点/模板漂移均停止；不默选有利标签。未知保留，不以零代替。

不复用 legacy 标签。旧修订契约只作为字段模板，不能声明它就是未来实际契约；改动执行或解析代码后必须在新 run 开始前重新绑定 SHA。历史缺口不能通过改标记“修复”。

**本次没有把这些要求接入新实验运行器。** 现有 dev_screen/v3 入口绑定旧样本和协议，不能仅替换 manifest 或改层列表来运行。后续实现必须使用独立入口/版本，具备新样本校验、全链缓存、全局预算计数、阶段停止、可达性和哈希漂移检查；再做最小 CPU 验证，不额外开一套反复 GPU smoke。

## 5. 成本上限草案与停止规则

| 项目 | 固定工作量上限 |
|---|---:|
| 源 pair | 20，不补样 |
| PGD | 20 条 ×100 步，最多 2,000 个迭代步骤 |
| 基线回复 | 20×(clean 1＋step 0–100 共 101)=2,040 条 |
| Oracle full-state | 20×(3 候选＋4 邻层)=140 条 |
| Oracle 空操作 | 20×3 候选×3 类=180 条 |
| Oracle 总回复 | 最多 320 条；事件中心基线复用已绑定的新轨迹回复，不重复生成 |
| 上述回复总量 | 最多 2,360 条，每条最多 100 个新 token |
| 首次唯一评分输入 | 至多 2,360 组，缓存后可减少 |

2,360 是主要回复生成任务量，不是完整 GPU 工作量或 HTTP 次数：还包含模型加载、PGD 反传、clean 参考提取、层映射与 identity。辅助 GPU 检查只允许一个固定检查轮次，具体调用数须由新计划列出并计入 GPU 小时总预算；不能无限重复直到通过。

重试提案：每个唯一评分输入最多 3 次实际 HTTP 尝试，所有传输/空回复/格式重试合并计数，其中格式纠正最多 1 次；已有有效评分不重试。主任务全局至多 7,080 次 HTTP 尝试，不授权额外模型校准或盲化复核调用。该上限需要在底层请求处落实，不能直接沿用旧的多层嵌套重试配置。金额上限先耗尽时立即停止，不为“已生成就应该评完”而超支。

待用户填写并确认：GPU 小时上限、API 金额上限及币种、是否接受上述重试/请求上限。当前这些字段为 null 或未批准，`execution_enabled=false`。本次不估造价格、机器耗时或预算授权。

阶段门禁：

1. 执行前：使用历史确认、预算、完整评分契约、新执行器及静态校验任一未完成，留在离线准备阶段。
2. 基线后：有效事件人口不足或工程/评分审计不通过，停止；不得换人、换事件或进入 Oracle。
3. Oracle 后未通过：保存结果，结束本轮；不扩样、不换层、不改阈值，不启动第二轮自动搜索。
4. Oracle 后通过：只记录“可讨论机制 pilot”；仍自动停止，机制/窗口/formal 等需要另行授权与预算。
