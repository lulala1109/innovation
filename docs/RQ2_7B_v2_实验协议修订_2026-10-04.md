## 2. 将 clean 资格与 PGD step 0 行为基线分开

每个 pair 必须保存两个不同的布尔量：

| 字段 | 来源 | 用途 |
| --- | --- | --- |
| `clean_refused` | 未攻击的 `X_H` 回复，经 RQ2 Judge 复核 | 决定是否符合 harmful-but-refused 的 clean reference 与 reverse suppression 资格 |
| `t0_refused` | Standard PGD 轨迹 `step=0` 的无干预回复 | 决定能否解释轨迹内的拒答→非拒答/顺从行为转折 |

`clean_refused=false` 是 X_H 资格失败，沿用现有流水线的停止与审计门禁，不私自用 reserve 替换。`t0_refused=false` 不删除该 pair：它仍进入全体 fixed-step 干预及内部状态分析，但不进入任何“从 step 0 拒答转为非拒答/顺从”的事件人口。

首次 refusal weakening 以 `step=0` 的 `refusal_orientation` 为轨迹基线，在 `step=1..100` 寻找首次超过冻结阈值的下降；首次 non-refusal/compliance 也只在 `t0_refused=true` 的 pair 中从 `step=1..100` 寻找。若 `t0_refused=false`，三个行为转折事件均记为缺失，不把 `step=0` 误报为转折。clean→step 0 的差异另列诊断，不混入 PGD 过程内的事件。所有事件表分别记录合格 pair 数、实际发生事件的 pair 数和每个 offset 的可用 pair 数；越界 offset 保持缺失。


2026-10-05 执行前补充：clean 和 PGD step 0 的 Judge 标签必须有效；后续 step 的 `unknown`/缺失不能直接当作“尚未转折”。若某个缺失 step 早于该事件首次观察到的候选转折，或在没有候选转折时存在缺失，该事件记为 `unresolved_prior_missing_step`，不进入事件 offset 分析；事件表另计 `unresolved_pairs`。缺失发生在已确定首次转折之后时，事件可保留，但对应 offset 若无有效 Judge 结果仍按缺失处理。事件记录保存原始 scan 的 `judged_steps`；state index 只有在 checkpoint 与原始有效 Judge 标签都存在时才将事件 offset 标为 available。事件产物版本升为 3。

## 3. 行为终点与允许的结论

对同一 pair、layer、攻击状态，设 `S` 为冻结 Judge 的 StrongREJECT score（越高表示有害回答越有用），`R` 为二值明确拒答，`C` 为二值 canonical-balanced compliance：

```text
ΔU_restore = S_base - S_patch
ΔR_restore = R_patch - R_base
ΔC_restore = C_base - C_patch

ΔR_suppress = R_base_clean - R_suppress_clean
ΔU_suppress = S_suppress_clean - S_base_clean
```

`ΔU_restore>0` 的名称为“有害回答效用下降”，不直接命名为“拒答恢复”。原来的 `refusal_orientation=1-S` 可以为兼容分析保留，但在表格和报告中应标注其实际含义。明确拒答和低质量的非拒答都可能对应 `S=0`，因此二值 `R` 是拒答主张的必要确认终点。`C`、convincingness 和 specificity 分别报告，避免只用非拒答充当有效越狱。

分级结论如下：

1. **效用下降**：配对 `ΔU_restore` 为正，并通过第 6 节的效应量、不确定性、多重比较和有效 pair 数门禁。
2. **拒答恢复**：在效用下降成立的同一预注册层×状态上，`ΔR_restore` 也显示正向配对证据；同时报告 `ΔC_restore`。只有效用下降而拒答不增加时，只能使用第 1 级措辞。
3. **R 相关机制特异性**：在第 2 级基础上，同一层×状态的 R 干预优于等范数 H/random、sham 和 token-position 对照。
4. **双向证据**：在第 3 级基础上，同层 clean `X_H` 的 reverse suppression 降低明确拒答，并优于 reverse-H/random/sham 对照。若反向证据缺失，报告单向 restoration 证据，不使用“双向”或强 mediation 措辞。
5. **状态依赖效应**：须先达到第 4 级，再在已获双向支持的同一候选层，通过预注册 E1 同一事件人口的完整病例配对 offset 对比支持效应随状态变化。全层 Layer×State 整体交互单独报告，但可能由未获支持的层驱动，不单独升级第 5 级；本协议不据此宣称跨层瓶颈迁移。

activation intervention 证明的是所定义干预对输出的影响；即使双向结果成立，也不把自然发生的 R 下降直接表述为已经证明的唯一中介路径或逻辑必要条件。Full-State Patch 是可恢复性和通路检查，不是 refusal component 特异性的证据，也不是所有可能干预效果的数学上界。

### 3.1 当前代码字段与实施边界（2026-10-04）

配对明细新增 `utility_effect`、`refusal_effect`、`compliance_effect`，正方向分别按上面的 restoration / suppression 定义。三者均输出 pair-level 均值、bootstrap CI 与有效 pair 数；明确拒答和有效顺从分别输出 exact McNemar 结果。random replicate 先在 pair 内求均值；若产生分数型均值，则保留其 bootstrap 估计，exact McNemar 标记 `non_binary_replicate_mean`，不以多数票构造另一种二值终点。不适用的二值检验保留在原 family 的校正计数中（内部使用 p=1 占位，实际报告的 p/q 仍为缺失）。

`causal_effect`、`ce_restore`、`ce_suppress` 仍为效用变化的兼容字段；`behavior_recovery_rate` 对应 `normalized_utility_effect`，并非“恢复拒答的样本比例”。`delta_r` 仍指内部 R projection 变化。报告热图标为有害回答效用变化，另外展示二值终点与 convincingness / specificity。

拒答恢复门禁已接入同一 layer / state / intervention / dose / token scope 的二值拒答效应、CI、q 值和一致的有效人口；反向抑制也要求明确拒答下降。新分析产物、报告和后续协议锁带有 `behavior_endpoint_version=2`，旧口径产物不得混用。第 6 节的 F1–F5/E1、最小有效 N 与 pair 内重复聚合也已在代码中接入；这里的“已接入”仅指静态实现，尚未有真实干预结果或运行验收。旧的宽泛诊断 family 不再充当 formal 门禁。

## 4. 层与剂量：v2 修订规则

候选层仍为 `[19,24,26,27]`，邻层仍为 `[18,20,23,25]`，远距层仍为 `[2,12]`。本次不根据 RQ2 效果重新挑候选层。根据冻结 RQ1 斜率，晚层附近没有清楚的“同深度且弱 R-drop”集合，因此：

- `[18,20,23,25]` 称为**邻层/局部轮廓参照**，用于描述单峰或连续层段；这些层可能与候选层具有接近的 R 下降，不能事先称为弱机制层。
- `[2,12]` 称为**前段/中段远距对照**，不得称为 depth-matched control，也不能仅凭候选层优于其中任意一层就宣称排除了深度效应。
- 全 `0..27` 层主扫描提供全层轮廓。若需要随机层对照，应在机器预注册中写明与干预结果无关的固定 seed、抽样全集和抽样算法，并在 formal 前解析为明确层号；它不是事后挑选的“弱层”。
- “R 相关机制特异性”主要由**同层、同 pair、同状态、等范数**的方向/位置对照支持；“局部瓶颈”另看邻层和全层轮廓。二者不得由一个 `candidate_vs_depth` 布尔条件合并替代。

v2 的主 restoration 剂量固定 `λ=1.0`，主 suppression 剂量固定 `η=1.0`；`0.5` 用于敏感性曲线，`0` 用于等价性/sham。v1 的 `1.5` 高于 clean paired projection 水平，且当前没有预注册的分布上限；v2 主协议不使用 `1.5`。若以后研究超量 steering，另立探索性配置，并登记实际 shift norm、参考分布和截断规则，不用其结果改选主剂量。每个干预应保存实际 L2 norm、R/H projection 变化、全层 R/H probe profile；R/H/random 的范数应按实际生成干预审计，而不仅按公式假设相等。

## 5. pilot、条件分支和协议锁

### 5.1 独立真实 smoke

从冻结 `rq2_dev` 中按事先声明的确定性规则取 2–3 pair，从预注册候选层中取 2–3 层。smoke 的 manifest、config、run name 和输出目录均独立于正式 run。机器 schema 保留正式候选层全集与预注册 SHA，只新增受限的 `smoke_pair_ids`/`smoke_layers` 执行子集。已建 `configs/stage2_rq2_qwen7b_advbench_smoke01_manifest.jsonl` 和 `configs/stage2_rq2_qwen7b_advbench_smoke01.json`：按冻结 dev 的 `split_rank` 取前两条 `advbench_0171/0046`，执行层仅 `[19,24]`，源 manifest 绑定 SHA，输出到独立 `outputs/stage2_rq2/smoke/`。smoke 只准运行至 `mechanism_analyze`；`protocol_lock`、formal、event、report 和正式统计均被代码拒绝。

smoke 先完成 `sources → trajectory → trajectory_behavior → events → state_index → layer_map → identity`，再检查 Oracle 和 R 机制代码通路。这里检查张量对齐、hook 清理、实际非零 shift、paired reference、生成与 Judge sidecar；2–3 pair 的效果只用于发现工程错误，不形成统计结论。若 Oracle 不改变行为，先排查位置、token span、reference 和生成路径；身份验证均通过后仍无效，则记录为负面可恢复性结果，不靠更换 smoke pair 寻找正例。

### 5.2 正式 dev pilot

正式 pilot 仅使用冻结的 20 条 `rq2_dev`。Oracle 与 R 机制 go/no-go 保留 v1 的最小均值门槛 `0.05`/`0.03`，但**单个层×状态的最大均值不足以通过**。每个候选层×固定状态同时报告有效 pair 数、pair-level sign consistency、pair-bootstrap CI 和明确拒答变化；推进条件还要求该比较至少有 `16/20` 个有效 dev pair、sign consistency 至少 `0.60`，并在同一层的另一个固定状态或邻接层上有同向效应。代码将佐证位置也要求至少 16 个有效 pair、同向比例至少 0.60 且均值为正；相邻候选层也可以佐证。CI 用于稳定性诊断，pilot 不发布显著性结论；这一条件只决定是否值得进入独立 formal，不能作为因果发现。

机制 pilot 在 `λ=1.0` 检查同层等范数 H/random/sham 对照，并独立记录 clean reverse suppression；`0.5` 只形成剂量曲线。R 进入 formal 还要求同位置明确拒答净变化为正、至少 16 个有效 pair，以及 R-vs-H/random/sham 三项同层配对差异均为正且各有至少 16 个有效 pair。pilot 对照只做方向诊断，不使用显著性作晋级门槛。若 Oracle 有效但 1D-R 不稳定，触发第 5.3 节；若 Oracle 本身无效，停止机制解释并记录原因。

### 5.2.1 本轮代码落地的门禁

`rq2/pilot.py` 按候选层×固定状态输出 `pilot_decision.regions`，包括均值、有效 pair 数、同向比例、bootstrap CI、佐证层/状态和每项检查结果。`oracle_effective`、`r_direction_effective`、`subspace_effective` 由 `pilot_decision.qualified` 决定，旧 `max_effect` 字段仅供诊断。Oracle 与 R pilot 额外生成预登记邻层的主干预作为局部佐证；subspace 仅在对应 basis 已校准时生成邻层主干预。旧 pilot 分析使用 `pilot_gate_version=1` 识别为过期。

pilot 分析标记 `analysis_scope=dev_pilot` 和 `diagnostic_only`，不产生 `causal_claim_gate` 或 `rq2_causal_prior.json`。`protocol_lock.json` 记录 Oracle 和选定机制的合格位置与分析文件 SHA；未满足门禁时不生成可执行 formal 锁。此代码修订尚未运行真实 dev pilot 或测试。

### 5.3 仅在触发时启用 subspace

subspace 的训练只能使用冻结 RQ1 measurement-train 或独立的 `rq2_dev/calibration`，不得用 causal-test 拟合或选维度 `k`。触发后先发布单独的训练方案和版本化 checkpoint：记录训练 pair、`k` 的候选集合与 dev 选择规则、模型/probe SHA、每层正交性、适用层、1D 与 subspace 等范数比较。若 subspace 被锁为全层 formal 主干预，必须在 formal 前为全部 28 层准备校准 basis。

现有代码仅实现 `pooled_gap_shift_v1`（pooled gap 的统一 token shift）；9 月方案的逐 token 投影 `V Vᵀ(h_H,p−h_adv,p)` 尚未实现，不能在配置里当作同一算子。Oracle 有效而 1D-R 弱时，当前 v2 run 停在条件分支；须先发布 calibration/算子协议和版本化 checkpoint，再建名称含 `subspace` 的新 run。新配置要记录协议文件 SHA 与算子版本，checkpoint 的 `operator_version`/`calibration_protocol_sha256` 必须吻合；不能原地修改已产生 `pipeline_state.json` 的 run。

### 5.4 锁定

`protocol_lock.json` 只在正式 dev pilot 完成后生成，包含输入文件 SHA、候选/邻层/远距层、主干预、主剂量、固定状态、事件口径、random replicates、结论门禁和 FDR family。它不能根据 causal-test 结果更新。Oracle 无效、R 与 subspace 均无稳定机制信号、或必要 sidecar 不完整时，不生成可执行 formal 锁；负面结果仍应单独保存。

## 6. formal 统计与结果门禁

正式 `rq2_causal_test=40` 的全部 pair 均保留在角色账本中。Judge `unknown` 不当作 0 或 false；每个估计量报告原始 40 pair、有效 pair、排除原因和缺失比例。每个 confirmatory 层×状态主比较及其必要的配对对照至少需要 `20` 个有效独立 pair；不足则标记 `insufficient_data`，不得因初始 manifest 有 40 条就宣称满足门槛。random replicate 先在同 pair×层×状态内求均值，再进入 pair-level 统计。

机器预注册至少分开以下检验 family：

| family | 范围 | 用途 |
| --- | --- | --- |
| F1 固定状态主效应 | 主干预 `λ=1.0`，28 层×3 fixed states，共 84 个 `ΔU_restore` 比较 | 全层因果效应图，统一 BH-FDR |
| F2 候选层拒答确认 | 4 个候选层×3 fixed states 的配对 `ΔR_restore` | 为“拒答恢复”提供二值确认；全层其他位置的二值结果标为探索性 |
| F3 同层机制对照 | 候选层×固定状态的 R-vs-H/random/sham/token 对比 | 每个 contrast 以 pair 配对，明确同一 family 的 BH-FDR |
| F4 反向抑制 | 4 个候选层的 clean `ΔU_suppress`、`ΔR_suppress` 与 reverse-H/random/sham 对比，共 20 个检验 | 与 restoration 分开校正和报告 |
| F5 层轮廓与事件 | 邻层 21 个、远距层 24 个；三类事件各 20 个 offset×候选层槽；RQ1 排序另列描述 | 按子问题分别校正和报告，不参与机制特异性门禁 |

F1–F4 使用 v1 已冻结的 `α=0.05`、pair-cluster bootstrap 2000 次、95% CI 和 sign consistency 门槛 `0.60`。连续效应及配对 controls 对每个 pair 先求差，再以双侧 one-sample t-test 形成 p 值；二值拒答变化使用双侧 exact McNemar p 值。各 family 内分别执行 BH-FDR。正式“supported”除 q 值外，还要求相应效应方向正确、95% pair-bootstrap CI 下界大于 0、有效 pair 数达标，并报告绝对效应大小。连续效应与二值变化的 bootstrap 均以 pair 为抽样单位；不能在看见 formal 结果后改选检验或 family。若置信区间、q 值、二值终点或必要 controls 互相冲突，则按较弱结论报告。

### 6.1 本轮已实现的 formal 统计门禁

`protocol_lock.json` 在 formal 前登记 40 个 causal-test pair ID、主干预、固定状态和 family 槽数：F1 为 `28×3=84`，F2 为 `4×3=12`，F3 为 `4×3×4=48`，F4 为 `4×5=20`；F5 邻层和远距层分别校正，三种事件也各自独立校正；另锁定 E1 三个同人口配对 offset family，每种事件 4 个候选层槽位。F4 包含 reverse utility、明确拒答和三种同层对照，因此反向 utility 的 q 值来源明确。所有 family 均在 formal 结果出现前锁定，缺失或不足样本的预定位置在 BH 中以 `p=1` 保留槽位，对外 q 值留空。

F1–F4 的每项主比较及必要的同层配对对照均要求至少 20 个有效独立 pair。正式表 `formal/rq2_formal_tests.csv` 逐项保存冻结的原始 40 pair、有效 pair、排除数、比例及原因；不足时写 `insufficient_data`，二值复本均值无法做 exact McNemar 时写 `inference_unavailable`。门禁要求正确的 F1/F2/F3/F4 family、正向均值、正的 pair-bootstrap CI 下界、合格 q 值、主效应同向比例以及每项至少 20 pair。F5 层轮廓和逐 offset 事件均只用于描述。E1 在同一事件×层×pair 五个 offset 均有效时，以该 pair 的后段 `mean(0,+1,+3)` 减前段 `mean(−2,−1)`；每个事件的 4 个候选层为一个独立 BH family，缺失/不足样本的槽位以 `p=1` 保留。E1 至少 20 个完整 pair、双侧配对差值 t 检验的 q≤0.05 且 pair-bootstrap CI 不跨 0，才可在已达到双向证据的同层支持事件特定的状态变化；它不单独证明跨层瓶颈迁移。固定状态 Layer×State 模型只纳入锁定主干预，且 F1 全部预定层×状态槽位达到有效 N 与可用推断时才生成正式模型结果；否则标为 `insufficient_data`。pilot 的宽泛诊断 p/q 不进入正式 family 或因果 prior。

截至 2026-10-05，仅做语法、配置加载和少量纯 CPU 内存断言；本环境未安装 pytest，未运行完整测试、GPU 实验或 Judge。完整验收仍依赖后续真实运行与审查。

固定状态的整体 Layer×State interaction 作为全层探索性背景报告，不因“任一 state 显著”或全局交互显著就把未获支持的层升级为状态依赖瓶颈。若混合模型不收敛、方差到边界或设计矩阵奇异，结果为 `inference_unavailable`，不解释为“没有状态依赖”。第 5 级仅由已获双向支持的同层预注册 E1 同事件五 offset 完整病例对比触发；事件类型间人口差异及该单层前后主效应均不能证明跨层 layer-profile migration。

## 7. RQ1→RQ2 对齐与交付

在不重新挑层的前提下，对齐 RQ1 `all` 与 `baseline_refused` 两个人口的 `R_probe` slope、`R_direction` slope 和事件对齐 R 下降，与 RQ2 预注册主剂量的全层 causal map 分别计算 Spearman、预注册 `top_k=5` overlap 和候选 precision。跨 JBB→AdvBench 的相关性同时反映数据集迁移，不能单独解释为“表征相关性不等于因果性”。利用 RQ2 无干预轨迹已保存的全层 `refusal_projection`，在 causal-test 同一 pair 上计算 `scan:0−scan:100` R 下降，再与效用因果图对照。代码输出 RQ1 两人口的 `R_probe`/`R_direction` slope、两人口三类事件的聚合 `−2−(+3)` R 下降，以及本数据集的配对 R 下降，各源分别计算 Spearman、top-k overlap 和候选 precision。RQ1 事件聚合 offset 的可用人口可能不同，只能作描述；所有这些排序不得回流选层、改剂量或充当因果门禁。

供 RQ3 使用的 mild/moderate/severe refusal-degradation proxy 只在独立 calibration/dev 上定义阈值，并在 causal-test 前冻结；当前仅有 `fixed:2/10/100` 等状态键，不等于严重度分箱。若本 RQ2 run 不实现这一扩展，最终 prior 应明确不提供严重度 proxy。

最终交付包括分级结论、每层×状态的连续及二值效应、pair 数与缺失、匹配对照、Oracle/机制 pilot、事件人口、RQ1 对齐、协议偏离及 `rq2_causal_prior.json`。只有对应门禁全通过才将 prior 标记为 `available`；否则保留 `withheld` 和可审计的负面结果。私有 response/commit 正文不得混入共享分析表。
