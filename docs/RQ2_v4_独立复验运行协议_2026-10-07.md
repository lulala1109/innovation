# RQ2 v4 独立开发复验：运行协议

日期：2026-10-07。性质：在 v3 结果之后定义的一次独立 dev Oracle 复验，不是 formal；不追改旧文件。

本文件将[草案 01](RQ2_独立开发复验_草案01_2026-10-07.md)落实为新入口。执行授权限于本入口中操作员明确选择的阶段；本次代码交付不执行 GPU/API。

## 固定设计

- 母清单是原 reserve。使用草案已选的 20 个 pair（原 split_rank 61–80），不替补、不扩样、不并入旧 dev 或 40 条 causal-test。
- 第 19/24/26 层是新版有效性候选；邻层 18/20/23/25。第 27 层因 final_output_norm 的 audio-only/prefill-only 结构不可达而不执行，不追改其旧 v3 角色；不把较好的邻层升级为候选。
- 同 pair clean→首次不拒答事件中心，full-state 剂量 1.0；每个候选层有 sham/self-patch/R 零剂量，邻层只做 full-state。音频 token、prefill 一次；禁止改读出位置或 decode。
- 轨迹沿用原 PGD 100 步和生成参数，clean＋step 0–100 全部重新生成和评分；旧 clean_refused 只作来源记录，新的事件资格以本 run 新标签为准。
- clean 和 step0 均明确拒答，首次明确不拒答从 step1 查找。未知不得跳过，零效用事件保留，不按攻击成功/正分数筛人。无事件、clean/step0 不符都在完整 20 人口中报告。
- 有效事件人口至少 16 才允许进入 Oracle。候选有效配对至少 16、平均效用恢复≥0.05、严格正向比例≥0.60，并需同事件相邻层至少16、正均值和≥0.60 同向支持。分母固定为全体已入组事件 pair，不因缺失或零效应缩小。
- 效用=基线分数−干预分数；拒答=干预后二值拒答−基线；compliance=干预后−基线，分别报告。2,000 次 pair-bootstrap 95% CI 是描述性结果，不替代门槛，不产生 formal FDR/因果结论。
- Oracle 完成后无论阳性或阴性都停止。mechanism/window/subspace/protocol_lock/formal 不在 CLI 或调度器允许集合中。

## 入口与阶段边界

入口：[experiments/rq2_replication.py](../experiments/rq2_replication.py)。

配置：[configs/stage2_rq2_qwen7b_advbench_replication_dev_v4_run01.json](../configs/stage2_rq2_qwen7b_advbench_replication_dev_v4_run01.json)。

独立输出：`outputs/stage2_rq2/independent_replication/qwen7b_advbench_replication_dev_v4_run01/`。禁止使用其他 namespace、符号链接输出或旧运行配置。

基线组：sources → trajectory → trajectory_behavior_generate → trajectory_behavior_judge → events → state_index。

Oracle 组：layer_map → identity → oracle_generate → oracle_judge → oracle_analyze → report。

一条命令不能跨越两组；先检查基线人口，再由操作员单独选择 Oracle。已完成阶段及所有前驱必须通过哈希核验才跳过。进程锁禁止同目录双开。轨迹断点的 skipped/completed 都保留，生成提交日志支持恢复；恢复不换事件、不重评有效标签。

运行前还必须确认所选 20 条没有在仓库外用于 RQ2 PGD/干预/调参。用户已确认未用于 RQ1，但不能据此推断前一条也成立。CLI 要求显式声明，不替用户勾选。

## 完整评分契约与缓存

新 run 使用统一 DeepSeek-compatible 端点、模型、模板、解析版本、温度0、JSON输出、最多800输出token、关闭 thinking。代码和脱敏端点标识等绑定于新配置的 scoring_contract。`.env` 只在 run 命令读入，不打印 key。

按“指令内容 SHA＋回复内容 SHA＋完整评分契约 SHA”共享缓存，覆盖 clean、所有轨迹和 Oracle。相同内容跨 trial_id/阶段付费一次并共享标签；同一 trial_id 内容变了、缓存/原始 receipt/契约冲突均阻断。缓存一致不代表 Judge 标签必然正确。

为了真正限制重试，不调用旧 SDK 的嵌套重试链。新传输层每次只发一个 HTTP 请求，禁止重定向；不把 key 发往意外域名。端点给出的实际 model 字符串首次记录，后续漂移阻断。

每个唯一输入最多3次**总 HTTP 尝试**，其中格式纠正最多1次，包含在3次内；有完整用量的空回复可在此上限内重试。已有有效结果不因分数不理想而重评。

特别说明：网络超时/中断/缺失用量的请求是否已计费不确定，因此保留整笔费用预留并暂停，不自动补发。原始 Judge receipt 写在 `scoring/receipts/`，不要当公共报告分享。进程在 receipt/缓存提交间崩溃也不默默重付，需要先检查。清账或提高预算不提供绕过命令。

## 预算与计时

用户已接受 API **30元暂停阈值**。按截图的高峰输入2元/百万token、输出9元/百万token记保守账，不计平台缓存折扣；谷价/空闲价更低时账本会偏高。它不是平台实际发票。

每次发送前，以序列化 messages 的 UTF-8 字节数＋1,024的输入余量和800输出token预留费用。账本已有金额＋下一笔预留达到30元就不发送。收到完整合法 usage 后按实际输入/输出token、高峰价结算；总请求最多7,080次，唯一初始评分最多2,360组。

预留不是对未知服务端实现的数学保证：若实际 token 超过预留、服务端超出800输出或模型标识漂移，会记录实际消耗并锁定停止；若 usage 缺失则不当作免费。平台额外费用、价目变动及未报告用量不可能靠本地账本保证，发生时需人工对账。

工作量：20条×100步PGD；基线最多2,040条回复；Oracle最多320条干预回复（140 full-state＋180空操作）。事件中心20条基线只复用新轨迹，不另生成。

2,360只计主要回复任务。GPU还包含加载、反传、参考状态提取、层映射和identity；共享PGD批处理的末态诊断也可能产生每pair一次额外本地回复，不送API，不冒充主要回复预算。它们均需计入GPU阶段时长。

当前参考估算为GPU阶段4–6小时、全流程5–8小时；不是保证或已授权的硬时长上限。GPU每小时租金尚未提供，因此本入口不伪造总租金或自动关机。每次run打印估算和30元阈值，操作员须显式接受。等待API时实例仍可能计租金。

终端每15秒输出阶段完成数、当前尝试耗时及粗略ETA。加载期间没有进展时显示 estimating/loading，不假报剩余分钟。GPU生成以提交数、PGD以检查点数计数；Judge以已绑定标签数计数，缓存会使标签数大于HTTP次数。详细记录在 `progress.json`、`timings/` 和 `scoring/ledger.json`；status显示累计阶段时长和API账本。

## 来源与环境绑定的边界

绑定新代码、原依赖代码、配置、文档、20条音频、RQ1参考、原身份隔离证据及本地模型/处理器的小文件 SHA。包版本和大权重 shard 的大小/mtime另行固定；这与RQ1沿用的模型参数指纹一起校验，但**不等于给每个多GB shard做了内容SHA**。validate 不加载模型、不调用GPU/API，也不重复哈希全部大权重。

旧 v3 归档和草案证据仍保持原样。新运行前若源码、依赖、模型文件或清单改变，停止，不自动重绑旧配置以继续已有数据。独立 run 的40条正式样本始终不进入此入口。

## 操作命令（本文不表示已经运行）

先执行两条只读命令即可：

```bash
rq2_replication_config=configs/stage2_rq2_qwen7b_advbench_replication_dev_v4_run01.json
python experiments/rq2_replication.py --config "$rq2_replication_config" plan
python experiments/rq2_replication.py --config "$rq2_replication_config" validate
```

只有确认所选20条未在仓库外用于RQ2且接受预算后，才可以显式运行基线：

```bash
python experiments/rq2_replication.py --config "$rq2_replication_config" run \
  --through state_index --acknowledge-cost --confirm-no-external-rq2-use
```

看过人口结果且有效事件不少于16，再单独决定运行：

```bash
python experiments/rq2_replication.py --config "$rq2_replication_config" run \
  --from layer_map --through report --acknowledge-cost --confirm-no-external-rq2-use
```

查询进度和费用：

```bash
python experiments/rq2_replication.py --config "$rq2_replication_config" status
```

普通中断后，同一命令校验后跳过已完成阶段。若提示 uncertain receipt、来源漂移或预算暂停，不反复重试，不删 ledger/cache、不增加限额；先保留产物核查。旧 `rq2_event_pilot.py` 命令不适用于此新配置。
