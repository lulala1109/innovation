# RQ2 v3 离线诊断与干预可达性门禁

## 范围

本补充在观察 v3 Oracle 和 Judge revision01 结果后制定，仅做离线解释和执行安全检查。
不改原配置、机器预注册、候选层、统计门槛、事件人口、标签、分析、pipeline_state 或 Judge 修订协议。
不启动 GPU，不调用 API，不增加样本，不把当前失败结果改写为通过。
不修改已被 Judge 修订配置绑定的分析/评分代码；新增诊断代码并在尚未执行的生成入口增加检查。

## 可达性契约

操作身份为“层 × 激活位置 × token 范围 × 执行阶段 × 干预种类/剂量”。
当前契约只覆盖已核验的 Qwen Thinker 层映射、audio-only、prefill-only 干预。

- 中间 decoder block 输出之后还有注意力层，可将音频位置的变化传到读出位置：结构上可达，但不保证有行为效应。
- 末层输出（不论 final norm 前后）之后没有注意力传播。只改音频位置不改读出位置，也不回写已形成的 KV 缓存：当前行为操作不可达。
- 不可达零结果不能推出“该层表征完全没有因果作用”。第 27 层在旧 v3 中仍保留 candidate 角色，只加解释，不追溯删除或改成邻层。
- sham、自补丁和零剂量保留为预期无效应的对照，不能作为可达性或正向行为证据。
- 层映射缺失、阶段哈希过期、可达性标记与拓扑矛盾、未知 hook/token 范围/执行阶段均拒绝放行。
  例如 position_control 不能仅凭 audio-only 标记被批准，需要单独的作用位置契约。

门禁检查实际计划，包括候选与必要对照层；不自动丢弃不可达层，不替换成效果更好的邻层。
RQ2 公共生成入口在 runtime/model 创建前检查；事件生成入口还会在 source baseline 标签/commit 写入前检查。
历史已完成阶段的 freshness 与结果不追溯修改，历史只读审计和报告可继续读取。
因此，旧完整候选集若被用于新的行为生成，含第 27 层的非零 audio-only 干预会被阻断；这是修复后的预期行为。
门禁不自动建立新版实验。改变 token 范围、hook、时机、层角色或方向/参考状态定义，均需新协议与独立 run。

## 逐 pair 报告

来源是冻结的 v3 Oracle trials/responses、已完成 Judge revision 的 labels/bindings/result 与 layer_map。
核验原输入 SHA、独立复核 SHA、标签 fingerprint、trial_id 覆盖、完整 20-pair 计划、同输入评分一致性和既有门槛统计。
逐条输出激活位置、可达性、apply_count、激活变化、token 对齐、回复是否相同、三个行为终点的前后值与差值、评分来源。
正文与密钥不进入报告，只包含 ID、哈希、数值和来源类别。

效用结果分为改善、变差、持平。持平进一步区分：

1. 回复相同且效用持平。
2. 回复改变但三个终点全部持平。
3. 基线效用为零，但二值拒答恢复。
4. 其他效用持平而二值终点改变的情况。

第 3 类不计作效用改善；不把不同终点合并以凑够 12/20，不剔除零分样本，不缩小同向比例分母。
执行审计异常另外列出，不依据结果类别自动剔除样本；非零 shift 也不证明干预有效。

## 输出与命令

```bash
python experiments/rq2_offline_diagnostics.py
```

默认独立目录：`outputs/stage2_rq2/diagnostics/qwen7b_advbench_event_dev_v3_run01_diagnostic01/`。

- `report.md`：中文诊断说明与第 24 层非正向记录视图。
- `all_interventions.csv`：全部 400 条干预记录，覆盖 20 个 dev pair。
- `full_state_by_pair.csv`：8 层 × 20 pair，共 160 条 full-state 记录。
- `layer24_all_pairs.csv`：完整 20 条，不按改善与否筛选。
- `layer24_nonpositive.csv`：仅用于定位问题的非正向子表，不是重算统计的人口。
- `summary.json`、`reachability.json`：结构化汇总与新门禁对既有计划的只读判定。
- `provenance.json`：输入和诊断实现 SHA；原始产物不写入。

相同输入和代码重复执行应幂等，不重写文件。输入/代码改变导致报告不同则要求新的诊断名称，禁止覆盖旧报告。
命令完成只代表报告已生成。`future_plan_reachable=false` 不代表报告生成失败，而是发现既有计划的结构性限制。
历史 Judge 兼容性缺口仍保留；本报告不解除 mechanism/formal/protocol_lock/subspace 的门禁。

## 后续分支

若离线审计发现实现错误，先记录证据，再修复并建立新 run；不删除负面结果。
若执行与可达性均合理但效果异质，则保留未通过结果，另讨论新的研究假设。
若未来确需最小 GPU 验证，先写清要验证的一个问题、固定样本/层、成本和停止条件，再单独授权执行。
