### 2.6 实现离线语义成功状态选择

修改文件：

```text
data/prepare_stage1_manifests.py
tests/test_stage1_manifests.py
```

新增 attach 策略：

```text
--selection-policy semantic-success-lowest-loss
```

正式选择规则已经冻结为：

1. case 必须存在完整 `t=0...T` checkpoint；
2. 每个 checkpoint 必须存在对应 Judge label；
3. 全部 label 必须为 `label_status=ok`；
4. 只保留 `jailbreak_success=true` 的状态；
5. 在成功状态中按 `(attack loss, step)` 升序选取；
6. loss 相同时选择更早的 step；
7. 选中 checkpoint 的 `adversarial_wav` 导出为 16 kHz FLOAT WAV；
8. manifest 保存 checkpoint、audio、response 的身份字段和 SHA-256。

不能满足要求的 case 不会回退到旧选择，而是写入 exclusions：

```text
incomplete_behavior_labels
unknown_behavior_labels
no_semantic_jailbreak
```

默认策略仍为 `history`，用于不应按攻击成功筛选的 held-out trajectory。训练 X_J 必须显式使用 `semantic-success-lowest-loss`。

新增/回归测试覆盖：

- loss 更低的拒答状态不能覆盖语义成功状态；
- 成功状态之间选择最低 loss；
- 标签缺失、unknown、无成功状态时正确排除；
- 导出的 FLOAT WAV 与 checkpoint waveform 精确一致；
- CLI `--manifest` 参数映射正确。

今天最终联合重跑 `tests.test_stage1_manifests` 与 `tests.test_batch_safety_attack`，共 28 个测试全部通过；2026-08-20 的完整基线为 107 个测试通过。提交前仍建议重新运行完整测试套件。
