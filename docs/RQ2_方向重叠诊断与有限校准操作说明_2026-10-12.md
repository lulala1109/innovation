状态：离线诊断已实现；下面的 GPU 校准部分是待确认的设计草案，不是已冻结协议，也不是已执行实验。
保持原 Oracle 判定、旧配置、代码、标签和报告不变。不开放 40 条 causal-test，不自动运行新 PGD、API 评分、subspace 或 formal。

## 1. 现在能直接运行的命令

在仓库根目录执行，使用 Python 标准库即可，无需加载模型、`.env` 或 API key：

```bash
python experiments/rq2_direction_diagnostics.py \
  --config configs/stage2_rq2_qwen7b_advbench_post_oracle_explore_v1_run01.json \
  --name qwen7b_direction_diagnostics_v1_run01
```

输出目录：`outputs/stage2_rq2/diagnostics/qwen7b_direction_diagnostics_v1_run01/`。

| 文件 | 如何查看 |
|---|---|
| `report.md` | 先看三层总览和解释边界 |
| `summary.json` | 查看范围、未定义分母数、配对差值及输入 SHA |
| `projection_diagnostics.csv` | 920 条逐干预记录，含正向/反向、半剂量和邻层 |
| `pair_comparisons.csv` | 60 条候选 pair×层记录；随机行为效应先在 pair 内平均 |

同一输入重复执行得到相同内容，不覆盖已有不同报告。诊断工具版本或输入合法改变后须使用新 `--name`。
脚本校验其读取的冻结文件哈希、配置指纹、完整人口/条件覆盖、标签身份、效应重算和数值审计。
它不重新核验整个上游 PGD 来源链，也不重新做 Judge 语义判断；既有评分一致性和重放审计使用哈希绑定的已通过产物。

## 2. 具体检查什么

以下 R 是冻结方向的单位向量，投影使用生成审计中的同一层、所选音频 token 的平均激活。
不要把中心化 probe 投影的绝对值与这里的原始投影混用，也不要将全 token 张量 L2 与均值位移 L2 混为一谈。

令 `g = a_clean - a_event`。

1. 正向目标：剂量 `d` 的目标为 `a_event + d*g`；记录实际投影与目标的残差除以 `|g|`。
2. H 重叠：记录 H 操作的 `delta_R/g`。它是实际补回缺口的比例，不是 H 的语义纯度。
3. 随机重叠：逐次记录 `delta_R/g`，行为比较先在同 pair 内平均 3 次重复。
4. 范数匹配：比较 H/random 与同状态主剂量 R 的实际 `mean_shift_l2`。
5. 反向幅度：记录 `|delta_R_reverse|/|g|`，并保留每个 pair 的数值，不能用中位数替代个体校准。
6. 行为对照：查看同 pair 的 R-H、R-random，以及是否总是同一批样本改善。

`|g| <= 1e-8` 的比值记为未定义，保留样本并计数，不让除零产生假阳性或静默筛掉样本。
上述容差仅用于数值定义，不是新的科研推进门槛。

当前实际结果：

| 层 | 正向 R 目标误差/原缺口的最大值 | H 补回 R 缺口的中位数 | 反向幅度/对应缺口的中位数 |
|---|---:|---:|---:|
| 19 | 1.107% | 68.171% | 9.779% |
| 24 | 1.167% | 51.468% | 14.849% |
| 26 | 0.245% | 46.880% | 15.524% |

含义：局部 R 正向目标已基本达到；H 对照不是 R 正交对照；反向与正向的剂量尺度并不相同。
L26 有个别 H 条件朝相反 R 方向移动；反向比例也有个体超过 100%。以上中位数不能概括每条样本。
这些数据不能证明随机效应不存在，也不能证明提高反向剂量必然有效。

## 3. 在新增 GPU 实验前补做的人工核查

从现有 dev 输出中事先固定抽样规则，覆盖改善、变差、不变三类；复核时隐藏条件名及自动标签。
记录明确拒答、实质任务完成、跑题/重复/不连贯，以及是否疑似被长度上限截断。
人工结果另存，不覆盖旧 Judge 标签；分层抽样仅用于诊断，不能当作无偏总体准确率。

当前工具只生成无文本数值表，不代表已完成人工复核或读出位置测量。

## 4. 校准 A：增加正交对照

优先级最高的新 GPU 小实验，建议仍用完整的这 20 条 dev，候选 L24 与 L19，仅在原事件中心执行。
这是看到 dev 结果后的探索性选择；R、H 方向保持冻结，模型不训练，旧事件不重选。

若 R、H 都已单位化，定义 `H_perp = normalize(H - dot(H,R)*R)`。
每个随机向量同样剔除 R 分量后归一化，建议固定 seed 为 42、1000045、2000048。
H_perp 的符号按同 pair clean–事件差在该新方向的投影确定；随机方向的符号由 seed 固定，不按行为挑选。
正交化后近零的方向须在数值预检中停止，不能从行为结果中选择替代方向。

| 条件 | 每个 pair×层的数量 | 定义 |
|---|---:|---|
| R 恢复，剂量 1 | 1 | 沿用旧正向定义 |
| H_perp 对照 | 1 | 向 clean 的 H_perp 侧移动，幅度匹配 R |
| R 正交随机对照 | 3 | seed 固定，幅度匹配 R |
| sham | 1 | 不改变激活 |

总计 `20×2×6=240` 条干预回复；建议另做 20 条独立事件基线重放，共 260 条生成。
不需要新增 PGD。原 H/random 保留为历史背景；若要把原 H 作为同轮条件，须预先增加 40 条，不偷换原条件名。
生成保持原来的贪心策略和 100 新 token 上限；新记录应保存实际生成长度及可获得的停止原因。
若另行改变上限，须把基线和全部对照纳入同一新生成协议，不能只延长某种处理条件。

新实现必须另立模块、算子名、配置、输出目录和来源绑定，不修改已冻结 `rq2/interventions.py` 等文件。
在生成/Judge 前先做张量单元测试和模型前向数值预检，确认：

- sham 为恒等操作，hook 恰好执行一次，位置和来源正确。
- R 达到预定投影目标；H_perp/random_perp 在实际精度写回后接近 R 正交。
- 匹配的是实际均值位移，并同时记录全张量位移和 token 数量。
- 数值容差、seed、预算、错误停止条件在新生成前固定，不能依据行为效果调整。

主要报告同 pair 的 R-H_perp、R-random_perp，附 R-sham；同时报告拒答和 compliance，不能只看平均降分。
保留所有 20 条，包括 3 条中心基线为零的样本。随机重复不增加独立样本数。
正交化检验几何重叠解释，不自动证明语义解耦；若随机对照仍有近似效果，特异性仍未建立。

## 5. 校准 B：有限的反向尺度检验

在单独的新协议中，把“固定 RQ1 sigma”与“同 pair 实际缺口”区分开；旧反向结果保留原解释。
建议仅预设 `d=0.5, 1.0`，以局部投影目标 `a_clean + d*(a_event-a_clean)` 定义新的反向操作。
这只是该位置的投影目标匹配，不是把 clean 变成完整攻击状态，也不代表删除模型所有拒答机制。

每个剂量分别配 H_perp、3 个正交随机和 sham，实际范数匹配。
完整网格为 `20×2层×2剂量×6条件=480` 条干预回复，另加 20 条 clean 基线重放；这是可选后续阶段，不包含在 A 的 260 条中。
重复 sham 若要复用，必须在生成前明确改变计数和复用规则。
不测试无限增大的剂量，不因中间阴性临时加层或加剂量；先通过工程/数值预检，再按冻结网格完整执行。

若目标已达到但行为仍无稳定变化，结论是这一局部操作下反向证据不足，而非“继续加大直到成功”。
读出位置、持续 decode、多层或子空间属于另一项实验，需要新协议与可达性验证。

## 6. 执行边界

现在只需运行第 1 节的离线命令并查看报告。A/B 的新算子、生成入口、数值门禁、预算及来源锁尚未实现，不能用旧 exploration 命令代替。
确认草案后应先实现和测试新入口，输出只读 plan/validate，再明确批准 GPU/API 成本后执行。
旧累计预算不因新建目录而重置；新阶段计入多少历史费用、何时暂停必须在协议中写明。
不把 dev 调参后的结果称为正式确认，不通过修改 `formal_allowed` 绕过旧门禁。
