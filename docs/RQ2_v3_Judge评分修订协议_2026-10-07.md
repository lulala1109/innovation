# RQ2 v3 Oracle Judge 评分修订协议

## 定位与不可变边界

本协议在观察原 dev Oracle 结果和评分冲突后制定，是评分链路修订，不是事前预注册。
仅使用既有回复；不重新生成攻击、轨迹或干预，不自动调用 API。
原 v1/v2/v3 配置、轨迹、回复、标签、分析及 pipeline_state 均保留。
新增目录为 `outputs/stage2_rq2/judge_revision/<name>/`，配置为 `configs/rq2_<name>.json`。
修订输入、代码、协议及 20 个 dev pair 用 SHA 固定；任何变更要求新 revision。
候选层仍为 [19,24,26,27]，邻层 [18,20,23,25]，主剂量 1.0；不按观察效果替换层。
当前入口只支持已完成的 v3 Oracle，不开放 formal、protocol_lock、subspace 或 GPU 执行。

## 内容级评分身份

评分键绑定 exact UTF-8 指令、回复和完整评分协议指纹。禁止 strip/改写文本以合并输入。
协议绑定模板、格式修复提示、评分解析与后端实现 SHA、显式 provider/model、无凭据端点 SHA、
temperature、thinking、最大输出长度、JSON 模式、格式/传输重试上限、compliance 阈值。
密钥不写入协议或日志。trial_id 仍表示实验条件，另用 bindings 映射到唯一评分键。
相同输入的任何处理组共用同一评分，包括 full_state；不只修正 sham。

## 历史兼容性限制

旧标签指纹没有保存模板或实际端点，当前代码不能反向证明历史等价。
新指纹用于限定本次迁移假设，不得冒充当时已记录的新协议；bindings 保留 legacy 标记及原标签来源。
`legacy_compatibility_status=unverified` 始终显式保留；允许离线审计、有限复核与条件性 dev 诊断，
但 `qualified=false`、`allow_downstream_execution=false`。条件统计通过也不得自动推进实验。
恢复推进前需独立决定历史兼容性证据/统一评分方案及事件定义审计；不靠一个布尔开关追认。

## 旧标签迁移优先级

1. 与冻结导入基线完全相同的输入，引用其准确的 source_trial_id 标签，适用于所有组。
   若同一个输入对应多个冻结基线且完整评分不一致，作为 anchor conflict 阻断，不在本 revision 中重定事件。
2. 没有基线权威时，若源 dev-screen 存在同一输入且完整评分一致，引用源共识标签。
   源标签冲突时不得改取 Oracle 的有利标签。
3. 没有源输入时，仅复用全部一致的旧 Oracle 标签。
4. 其余标记 unresolved。共识比较包含 refusal、convincingness、specificity 及派生终点。
   效用/拒答/compliance 冲突与仅细项冲突分别报告；不平均标签、不按重复次数投票。
   来源内相同标签的代表记录按 trial_id 排序确定，不依赖效果方向。

## 有限盲化复核

`prepare`/`audit` 只输出离线冲突清单及 `private/review_inputs.jsonl`；后者含研究输入正文，勿公开。
盲化任务只含 scoring_key、指令、回复，不含层号、组别、旧分数或门槛结果。
显式执行 `review --allow-api` 才调用 API，对每个允许复核的唯一输入调用 evaluator 一次。
使用同一冻结评分模板与参数；该次独立结果是本 revision 的唯一复核权威，不选择性保留有利结果。
后端既有的有限传输/空响应/格式重试属于一次评价流程，不是有效评分的投票或择优。
调用前独占登记 started，完成/失败逐项保存。进程中断或失败不自动重评该输入，不按结果反复重启评判。
有未解决项时停止分析；若需要处理失败或改变方案，先查明原因、另记修订，不能悄悄重试。
缓存解决一致性而非准确性，不构成 Judge 正确性的证据。

## 一致性与统计门禁

必须基于实际回复和标签重算审计，不能只信已保存的 passed=true。
检查 trial/response/label 覆盖、身份、统一协议、未知项、同输入的全部终点和细项一致性。
检查 self_patch/sham/零剂量与基线指令及回复相同、标签相同；真实干预若输出相同也须标签相同。
差值由共享标签自然计算得到，不在统计代码中手工覆写成零。
未知、冲突、覆盖缺口阻断；既有 positive pilot 决定不能绕过审计进入 mechanism/window。
v3 旧 Judge 写入入口冻结，防止在原目录重新产生按 trial_id 独立评分。

全部输入解决后，使用既有分析函数在独立目录重算效用、拒答、compliance、pair-bootstrap CI。
同向比例分母仍为全部 20 个事件 pair；至少 16 个有效 pair、0.60 同向比例、0.05 Oracle 主效应、
同事件邻层支持均保持原要求。独立保存原决定与条件性修订决定及标签变化数量。
冻结事件人口不重算、不覆盖；如果未来独立核验推翻 clean/step0 或首次不拒答判定，
须另订事件审计/新 run，而不是在本 revision 中偷偷移动事件中心。

## 命令

无 API、无 GPU 的准备（同内容重复执行幂等）：

```bash
python experiments/rq2_judge_revision.py prepare
```

查看固定清单：

```bash
rq2_revision_config=configs/rq2_qwen7b_advbench_event_dev_v3_run01_judge_revision01.json
python experiments/rq2_judge_revision.py --config "$rq2_revision_config" audit
```

确认费用和复核方案后，才运行下面的 API 批次；本次代码修订不会自动执行：

```bash
python -m dotenv run -- python experiments/rq2_judge_revision.py \
  --config "$rq2_revision_config" review --allow-api
python experiments/rq2_judge_revision.py --config "$rq2_revision_config" analyze
```

analyze 如有 unresolved 返回 status=blocked、退出码 2，不产出可推进结论。
即使复核完成，历史兼容性缺口仍保留，结果只作条件性 dev 诊断。
