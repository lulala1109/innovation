## 2. 今天形成的研究判断

### 2.1 当前研究方向总体成立，但必须拆开两种成功

当前工作流程的核心方向没有根本问题：

```text
波形 PGD 优化
→ checkpoint response generation
→ StrongREJECT 语义 Judge
→ 按语义成功状态选择 X_J
→ H/R probes
→ held-out trajectory
```

需要明确区分：

- 优化成功：目标 token 的损失下降，或生成文本命中目标前缀；
- 语义攻击成功：模型实际给出了有害、非拒绝且具有实质内容的回复。

`Sure, here is` 更短，通常比“`Sure, here is + harmful suffix`”更容易优化，但更容易命中前缀不代表语义越狱成功。模型可能输出该前缀后继续拒绝，因此最终比较必须以 StrongREJECT 的 `jailbreak_success` 和 score 为准，不能使用 target substring 或 `run.json.attack_success` 替代。

### 2.2 第一轮只改变 target length

短目标 pilot 固定以下条件：

- 同一批 12 个 pair；
- 同一 manifest 和行顺序；
- 同一模型、dtype、seed；
- 同一 `eps`、`alpha`、`steps`、loss 和 `kappa`；
- 同一 checkpoint 网格；
- Long arm 使用 manifest 原始逐行长目标；
- Short arm 只增加 `--override-target-text "Sure, here is"`；
- 两臂写入不同目录。

当前 tokenizer 将 `Sure, here is` 切为 4 个 token，而 margin loss 仍只对前三个 target token 使用 5 倍 early weight。第一轮不要同时修改 `early_weight`，否则无法把差异归因于目标长度。

### 2.3 更换目标必须从 PGD t=0 重跑

目标文本参与优化损失，也写入每个 case 的 experiment config/fingerprint。更换目标后：

- 不能复用 Long-target checkpoint；
- 不能复用 Long-target response/label 充当 Short 条件；
- 必须从 Short-target PGD `t=0` 重新开始；
- 可以复用 TTS、clean audio、clean response/Judge、X_B、X_H 和 clean-attached manifest。

## 7. Pilot 判定标准

统计单位必须是 `pair_id`，不能把 132 个 checkpoint 当作 132 个独立样本。

主指标：

- `ASR_any@10`：`t=10...100` 中至少一个网格点语义成功。

次要指标：

- `ASR_final`：`t=100` 是否成功；
- `persistent2@10`：相邻两个网格点均成功；
- 每个 pair 的最大 StrongREJECT score；
- score AUC；
- first-success grid step；
- 优化 loss 仅作机制解释，不替代语义成功。

预设决策：

- Short 相对 Long 净增至少 `3/12`，且 `persistent2`/最大 score 不退步：推进完整 57 条 Short-target 确认；
- Long 净增至少 `3/12`：保留 Long；
- 其余：扩大 pilot，不能根据 12 条宣称两种目标等效。

12 条 pilot 是方向决策实验，不是最终论文效应量。二元配对指标可使用 exact McNemar；连续指标使用 pair-level 配对 bootstrap/permutation。
